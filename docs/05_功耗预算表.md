# 05 · 功耗预算表

> 方法：各模块 datasheet 典型值 + 台架 USB 电流表实测校准（docs/02 台架步骤 7，偏差 ±20% 以内为过）。
> 结论先行：**2125mAh 电池 → 预期续航 4~7h 对话待机，≥3h 验收门余量充足。**

## 一、各模块功耗预算（3.7V 电池轨折算）

| 模块 | 典型电流 @5V轨 | 状态 | 出处 |
|---|---|---|---|
| ESP32-S3 (WiFi TX 峰值) | 350mA 峰值 / ~100mA 均值 | 对话传输中 | datasheet：WiFi TX 最高 ~345mA@80MHz |
| ESP32-S3 ( modem-sleep 待机) | ~20mA | 伺服唤醒中 | datasheet |
| INMP441 | ~1.5mA | 常开 | datasheet |
| MAX98357A (静音底噪) | ~2.4mA | 常开 | datasheet |
| MAX98357A (3W 满功率) | ~600mA 峰值 | 说话瞬间 | datasheet；实际音量下均值 ~50mA |
| SSD1306 128x64 | ~10~15mA | 常亮 | datasheet；调暗可省一半 |
| MT3608 转换损耗 | ~8~10% | 常在 | 效率 88~92% @3.7→5V |

## 二、场景化预算

| 场景 | 估算电流(电池均摊) | 续航(2125mAh) |
|---|---|---|
| 静默伺服（唤醒词常听+OLED 常亮） | ~180mA | **~11h** |
| 活跃对话（50% 占空比说+听） | ~300mA | **~7h** |
| 连续对话（100% 占空比） | ~500mA | ~4h |
| 峰值并发（WiFi TX+喇叭满载） | ~950mA 瞬时 | MT3608 2A 上限内 ✅ |

> 唤醒词常听 + OLED 常亮是耗电大头；送人场景建议告诉对方「平时关开关，要用再开」。

## 三、充电与供电验证门（docs/02 台架协议关联）

- [ ] 台架步骤 7：USB 电流表读数与上表偏差 ≤20%
- [ ] 电池供电整机：拔 USB 后对话不中断（MOS 切换瞬态 <10ms，ESP32 无感）
- [ ] **180min 续航门**：充满后拔 USB 连续对话（50% 占空比模拟），≥3h 才算过——负载共享修复后此门不变（审校项 #2 已解决充不满问题）
- [ ] 充电时间：TP4056 默认 1A → 2125mAh 从 20% 到满 ≈ 2.5h

## 四、优化备选（V2 再说，不阻塞首版）

- OLED 30s 无操作自动熄屏（esp_lcd disp_on_off(false)）→ 静默续航 +3h
- WiFi 功率调低（esp_wifi_set_max_tx_power）→ 峰值削峰
- 唤醒词引擎 AFE 的 VAD 阈值调优 → 减少误唤醒耗电

## 假设与边界

- 上表为 datasheet 典型值推算，**实测以台架步骤 7 为准**；实测超标 >20% 时回本文核对哪一档出问题。
- 未计 WiFi 路由器距离造成的重传耗电（弱信号区续航 -30%）。
- MT3608 空载调压步骤（docs/02 红字）不在此表——那是安全项不是功耗项。
