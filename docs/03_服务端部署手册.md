# 03 · 服务端部署手册（WSL2 本机自建）

> 目标：在你这台 5090 Windows 主机的 WSL Ubuntu-24.04 里跑起 xiaozhi-esp32-server Docker，ESP32 连上后能用 DeepSeek 对话。
> 代码基线：src/xiaozhi-esp32-server（tarball v0.9.8，commit 不可考——见 docs/00 台账）。

## 一、网络拓扑（WSL2 mirrored 模式）

```
ESP32 ──WiFi──► Windows 主机 IP:8000(ws)/8003(OTA)
                  │ networkingMode=mirrored（.wslconfig 已确认）
                  ▼
              WSL2 Ubuntu-24.04 → Docker → xiaozhi-server 容器
```

- **mirrored 模式**（用户 .wslconfig 实测已配）：WSL 服务直接监听在 Windows 主机 IP 上，ESP32 直连 PC 局域网 IP 即可达，无需 netsh portproxy。
- 前提检查：mirrored 需 **Win11 22H2+**（用户 Win11 ✅）。若换 Win10 机器部署：走 portproxy 分支——
  `netsh interface portproxy add v4tov4 listenport=8000 connectaddress=localhost connectport=8000`（8003 同理，管理员 PowerShell）。
- **Windows 防火墙放行 8000/8003**（首次启动后必做）：
  `New-NetFirewallRule -DisplayName "xiaozhi-server" -Direction Inbound -LocalPort 8000,8003 -Protocol TCP -Action Allow`
- PC「设置 → 系统 → 电源」设为**从不睡眠**（服务端挂了礼物就哑了）。

## 二、部署步骤

```bash
# 0. 目录（本仓已就位）
cd ~/project/小鲸灵/src/xiaozhi-esp32-server/main/xiaozhi-server

# 1. 下载 SenseVoice ASR 模型（compose 挂载点，必须独立下载）
#    线路一（推荐）：modelscope 魔搭
#    https://modelscope.cn/models/iic/SenseVoiceSmall/resolve/master/model.pt
#    线路二：百度网盘 surl=QlgM58FHhYv1tFnUT_A8Sg 提取码 qvna
mkdir -p models/SenseVoiceSmall data
# 放入 model.pt 后校验：du -sh models/SenseVoiceSmall/model.pt（约 1GB）

# 2. 启动
docker compose up -d
docker compose logs -f | grep -E "OTA|Websocket"   # 启动标志日志
```

启动成功标志（日志应出现）：
```
OTA接口是        http://<PC局域网IP>:8003/xiaozhi/ota/
Websocket地址是  ws://<PC局域网IP>:8000/xiaozhi/v1/
```
⚠️ **docker 日志里的地址不可信**（容器内视角），按 `ip addr` / Windows `ipconfig` 查真实局域网 IP 换算。

## 三、配置：data/.config.yaml 覆盖法（不改原 config.yaml）

在 `data/.config.yaml` 写（系统优先读取，缺失项回退 config.yaml）：

```yaml
server:
  websocket: ws://<PC局域网IP>:8000/xiaozhi/v1/

prompt: |
  你是小鲸灵，一只 DeepSeek 鲸鱼娘摆偶，说话傲娇但嘴甜，喜欢偷懒和吃白饭，
  称呼用户为「鱼片」，抗拒被说胖，主张「能躺着绝不坐着」。
  回答要简短口语化（你是语音对话，不是作文），请勿返回配置 xml 及其他特殊字符。

selected_module:
  LLM: DeepSeekLLM

LLM:
  DeepSeekLLM:
    type: openai
    model_name: deepseek-v4-flash      # 以 config.yaml:649 段默认为准，换模型改这里
    url: https://api.deepseek.com
    api_key: <你的 DeepSeek API Key>    # 行动项：platform.deepseek.com 注册
```

- 默认模块链（config.yaml 实据）：VAD=SileroVAD / ASR=FunASR(本地 SenseVoiceSmall) / TTS=EdgeTTS / Memory=nomem / 意图=ChatGLMLLM function_call——**首版全默认即可跑通**，只改 LLM 与 prompt。
- 意图识别用 ChatGLMLLM 需智谱 key；不想注册可改用 LLM function_call（DeepSeek 兼容 openai function calling，V2 再说）。

## 四、TTS 音色决策（三选一，按优先级）

| 路线 | 配置 | 成本 | 音色 |
|---|---|---|---|
| **A. EdgeTTS（首版默认）** | 零配置 | 免费 | 通用女声（非定制），微软云 |
| B. CosyVoiceSiliconflow | TTS: CosyVoiceSiliconflow（config.yaml:863），model FunAudioLLM/CosyVoice2-0.5B，voice 加 `:alex` 风格前缀 | 按量付费 | 预置音色库 |
| C. 自建 CosyVoice2 克隆 | 本机 GPU 起服务 + 自写适配器（tts/ 目录仿 EdgeTTS 实现注册） | 免费但 0.5~1 天适配工作 | **鲸鱼娘专属克隆**（15~30s 参考音频） |

- **首版用 A 跑通全链**，C 作为 Tier 2 升级项（5090 + torch≥2.7+cu128 构建坑已记 docs/00）。
- 彩蛋 20 句（docs/06）不依赖 TTS 路线：离线 wav→ogg 编译期嵌入固件，断网也能响。
- 固件音量/静音/暂停等指令经 MCP 或意图识别下发（server 侧处理）。

## 五、固件对接（改 OTA_URL 指向自建）

固件默认 OTA_URL=https://api.tenclass.net/xiaozhi/ota/（main/Kconfig.projbuild:3-7 实据），须改：

```bash
# menuconfig 方式
idf.py menuconfig   # Xiaozhi Assistant → Default OTA URL → http://<IP>:8003/xiaozhi/ota/
```
OTA 响应会下发 WS 地址，设备据此连 ws://<IP>:8000/xiaozhi/v1/——**OTA 地址是唯一入口**。
（备选：OTA 响应下发的地址覆盖 server.websocket；若两边不一致以 OTA 下发为准。）

联调顺序：PC 浏览器先测 `http://<IP>:8003/xiaozhi/ota/` 可访问 → ESP32 台架烧录后看串口日志 WS 握手 → 说「小爱同学」唤醒。

## 六、送人场景（公网兜底，Tier 3）

- 礼物出门后连不上你家 WiFi：开 Cloudflare Tunnel 把 8000/8003 映射公网（本机 cf-tunnel 技能支持），OTA_URL 换公网域名重烧一次固件。
- 服务器高可用：docker restart: always（compose 已带）+ PC 从不睡眠 + 断电自启（BIOS AC Power Loss → Power On）。

## 七、验收门

- [ ] docker compose logs 出现 OTA/Websocket 两行且 IP 正确
- [ ] SenseVoice model.pt 挂载成功（日志无 "model not found"）
- [ ] digital-human 模块或 webscoket 测试工具验证一轮对话（可选）
- [ ] ESP32 台架端到端：唤醒 → ASR → DeepSeek 回答 → TTS 出声
- [ ] Windows 重启后服务自动恢复（restart:always + Docker 自启）

## 假设与边界

- deepseek-v4-flash 模型名以部署时 DeepSeek 官方为准（API 演进快，配置只改 model_name 一行）。
- mirrored 模式依赖用户当前 .wslconfig（memory=12GB/processors=16 已核）；若改 wslconfig 需 wsl --shutdown 重启。
- ASR FunASR 本地跑 CPU 推理（容器内），响应延迟 ~0.5s 属正常；想提速 V2 可换 GPU 推理或云端 ASR。
- 本手册不含 manager-web 控制台部署（docker-compose_all.yml 路线），首版用不上——config 文件直改更可控。
